# Основной адрес с www

В production (`DEBUG=False`) сайт использует `https://www.marishkinirecepti.ru`.
Старое значение `SITE_URL=https://marishkinirecepti.ru` автоматически приводится
к основному адресу. Обе формы домена добавляются в точный список ALLOWED_HOSTS
и HTTPS-источников CSRF. Звёздочки и разрешения для произвольных поддоменов не нужны.

Все страницы без www перенаправляются на www с сохранением пути и query.
Для обычных страниц используется код 308.
Canonical, Open Graph, sitemap, новые ссылки возврата из ЮKassa и ссылки из админки
формируются с www. При смене адреса обновление Docker достаточно для приложения;
Nginx должен уже обслуживать оба домена с действующим сертификатом.

Особенности совместимости:

- Уведомления ЮKassa продолжают обрабатываться по старому HTTPS-адресу без редиректа.
  Для новых настроек используйте `https://www.marishkinirecepti.ru/payments/yookassa/webhook/`.
- Старые страницы заказа, скачивание и возврат из оплаты тоже открываются на www.
  Доступ старого покупателя переносится через одноразовое разрешение на 120 секунд,
  привязанное к отдельной host-only сессии www. Разрешение погашается в транзакции,
  не работает как cookie входа и не может быть использовано другим браузером.
  Исходные sessionid не передаются через URL. Заголовки no-store и no-referrer
  установлены на всех шагах переноса; исходные заказы не меняются.
- Ранее открытая форма на домене без www переводится на новую форму www кодом 303
  до создания платежа; нужно снова заполнить её и подтвердить условия.
- Проверка `/health/` через localhost остаётся доступной контейнеру; запрос по
  домену без www перенаправляется на www.
- Cookie сессии остаётся привязанной к точному хосту. Передача sessionid через URL
  или раскрытие cookie внешнему сервису на делегированном поддомене link не используются.

Проверка после обновления:

```bash
curl -I 'https://marishkinirecepti.ru/legal/offer/?from=test'
curl -I 'https://www.marishkinirecepti.ru/'
```

Первый запрос: 308 с Location `https://www.marishkinirecepti.ru/legal/offer/?from=test`.
Второй запрос: 200, без повторяющегося редиректа.

Ожидаемый ответ на обработанное уведомление ЮKassa — HTTP 200:
https://yookassa.ru/developers/using-api/webhooks
