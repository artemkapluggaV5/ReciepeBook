# Эксплуатация после перехода на прямое скачивание

Текущие команды установки, backup и обновления находятся в README.md.
Сервисы Compose: db, init, web. Почтового worker и настроек SMTP/API больше нет.
При обновлении сначала остановите старый delivery-контейнер и web, сохраните pg_dump,
затем git pull и docker compose up -d --build --remove-orphans. Не удаляйте volumes.
orders/0003 удаляет email и статистику писем, сохраняя оплаты и download tokens.

Следите за /health/, ошибками pdf_missing, длительными pending и webhook rejection.
Страница скачивания не требует почтового аккаунта. Утерянный доступ восстанавливается
через поддержку после проверки оплаты сотрудником; публичного восстановления нет.
Пересылка ссылки из Admin не восстанавливает сессию покупателя: действие разрешает
скачивание только в текущей сессии администратора.
Приватный PDF и его резервные копии никогда не размещаются в public-media/static.

Настройте HTTPS через Nginx и Certbot для домена, proxy только к 127.0.0.1:8000,
брандмауэр с разрешёнными SSH/HTTP/HTTPS. Не открывайте PostgreSQL в Интернет.
Нужны регулярные зашифрованные backup PostgreSQL, приватных/публичных файлов и .env
вне VPS и проверка восстановления. Не сбрасывайте InvId sequence и платёжный журнал.

Возврат денег сверяется оператором с кабинетом провайдера; соответствующий заказ
должен получить refunded через контролируемый административный процесс.
Потерянные webhook автоматически не запрашиваются у провайдера: проверяйте pending.
Фискализация и правовые документы должны соответствовать настоящему продавцу.
