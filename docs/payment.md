# Оплата через ЮKassa

Документация: https://yookassa.ru/developers/payment-acceptance/getting-started/quick-start
Уведомления: https://yookassa.ru/developers/using-api/webhooks

Единственный активный провайдер — ЮKassa. Старые платёжные маршруты и виджет удалены.
Исторические миграции и учётные записи LegacyInvoice сохранены: удалять сведения об
оплате и ломать ссылки уже оплативших покупателей нельзя.

## Настройка тестового магазина

В существующем серверном проекте (с заполненным .env):

```bash
python3 deploy/configure_yookassa.py --shop-id 1527129
```

Введите test_ ключ в скрытый запрос. Скрипт сохраняет только в локальном .env,
удаляет старые платёжные переменные, включает SALES_ENABLED=True и
YOOKASSA_TEST_MODE=True. Пароли БД, SECRET_KEY, настройки домена и PDF сохраняются.
Не передавайте секрет как аргумент командной строки и не добавляйте .env в git.

В кабинете тестового магазина ЮKassa → Интеграция → HTTP-уведомления:

- URL: https://www.marishkinirecepti.ru/payments/yookassa/webhook/
- события: payment.succeeded, payment.canceled, refund.succeeded.

Отдельные SuccessURL/FailURL в кабинете не нужны. Подписанный return_url передаётся
в каждом запросе создания платежа. Не вставляйте туда чужой номер заказа вручную.

## Проверка и выдача PDF

Цена, RUB, название и UUID заказа берутся из БД; capture=true.
Создание использует сохранённый Idempotence-Key и неизменный payload. После сетевого
таймаута повторяется тот же запрос. После 23 часов неоднозначная попытка блокируется
до разбора поддержкой: гарантия идемпотентности провайдера ограничена 24 часами.
Новый платёж после подтверждённой отмены создаётся с новым ключом.

JSON уведомления служит сигналом для GET /v3/payments/{id} с серверной авторизацией.
Проверяются ID, магазин recipient.account_id, test, metadata.order_id, сумма, валюта,
status=succeeded и paid=true. Сам редирект, query status=paid, JSON paid=true и статус
waiting_for_capture не открывают скачивание. Уведомления обрабатываются повторяемо.
При сетевой ошибке webhook возвращает 503 для повторной доставки.

Страница заказа независимо опрашивает тот же API (не чаще раза в 5 секунд на заказ).
Поэтому пропущенное уведомление не блокирует выдачу после возвращения покупателя.
При отмене открывается /payments/fail/ с повторной оплатой. При задержке или ошибке API
покупатель видит ожидание, а не ложное подтверждение. Подписанный return требует сессию, в которой был оформлен заказ: пересланный
return_url не создаёт доступ в чужом браузере. Публичный UUID не даёт доступа.

После успешной проверки: закрытая страница заказа с обложкой и «Скачать сборник».
Сайт не отправляет сборник по почте. PDF остаётся в приватном volume; ссылки подписаны, ограничены
по сроку и числу скачиваний, а также требуют сессию покупателя. После очистки cookies
или перехода на другое устройство покупатель обращается в поддержку. Ссылки из Admin
открываются только в текущей сессии сотрудника, их нельзя использовать для передачи доступа. Подтверждённый возврат (включая частичный) отзывает доступ.

## Диагностика

```bash
docker compose exec web python manage.py diagnose_payment UUID_ЗАКАЗА
docker compose logs --tail=80 web
```

Диагностика не меняет оплату и не выводит ключи/подписанные URL.

## Боевые продажи

Настроить реальный магазин и ключ в .env; YOOKASSA_TEST_MODE=False, затем
`python3 deploy/enable_payments.py --mode live`. Тестовый ключ в live не принимается.
Проверить реальный PDF, юридические страницы и фискализацию (`check_launch`).
Для подтверждённого владельцем сервиса «Чеки от ЮKassa» сайт собирает email покупателя
для чека и передаёт `receipt` при создании каждого боевого платежа. Чек отправляет
ЮKassa, скачивание сборника по-прежнему происходит на сайте. `YOOKASSA_VAT_CODE=1`
означает «без НДС» (подтверждено владельцем), а не ставку 0%. Предмет расчёта —
`intellectual_activity`, способ — `full_payment`, количество — одна электронная книга.
Email, позиции, сумма и ставка чека сохраняются в приватной записи счёта до HTTP-запроса:
повтор после таймаута использует прежний payload и ключ идемпотентности.
В тестовом магазине чек можно включить через `YOOKASSA_RECEIPTS_ENABLED=True`.
После обновления с версии без чеков откройте главную заново: форма получит новый ключ,
старые попытки и оплаченные заказы сохранятся. Проверьте регистрацию настоящего чека
в кабинете ЮKassa после первого боевого платежа.

Цена меняется в Admin → Products → Product → поле `price`. Главная и новые заказы
берут цену из товара; сумма уже созданного заказа сохраняется. Перезапуск не нужен.
